# Task-centered UI/UX

Apply proportionally to the changed flow. Follow scoped project design and skills
first. Without applicable project design use the installed baseline's design
router; do not import defaults into an established product by surprise.

Read the real entry point and handlers. Screenshots establish visible layout,
not hidden business rules. Do not invent domain terminology, prices, permissions,
mechanics or transitions. Reuse settled decisions; ask about material ambiguity
while continuing independent authorized work.

For a new/substantial flow, describe actor/context, intended outcome, entry →
decision → commitment → result → continuation, decision information, applicable
states, exit/persistence and verification evidence. Use an existing feature note
or concise task reasoning, not a new document for every small change.

Give each decision a clear action or explicit choices. Keep subject/ownership
visible and refresh dependent comparisons/eligibility when selection changes.
Show current versus proposed values and totals; do not require remembering another
screen. Use recognizable labeled collections, a clear inspector where useful,
scoped filters, selection/focus and preserved position. Reveal advanced options
without hiding required information. Explain unavailable actions and the next step.

Before paid/irreversible actions, show exact scope, cost and consequences. Do not
add confirmation to harmless navigation. Respect protected selections and disclose
exclusions. Pending actions acknowledge input and prevent unsafe duplicate commits.
On uncertainty, reconcile the outcome before suggesting another destructive retry.

Show committed results where the action happened, with a relevant continuation.
Back/Cancel before commitment must not mutate; closing a committed result is not
rollback. Preserve valid work on failure and offer feasible recovery. Adapt error
detail to the audience, never expose secrets or disguise failure as success.

Use project input/localization conventions and real platform semantics. Essential
information needs more than hover/color. Check actual-size text, long names,
wrapping, clipping, scroll bounds, layering and hit targets. Keep readable contrast,
visible keyboard focus, accessible names, predictable input and a way back.
Respect reduced motion; decorative effects must not obstruct tasks.

Before calling the experience ready, check the actual journey:
1. Intent, subject and next action are understandable.
2. The primary action reaches its promised result without hidden detours.
3. Costs, requirements, comparisons and consequences are visible when needed.
4. Back/Cancel, empty/unavailable and failure/retry preserve control and context.
5. Input and layout work at supported sizes.
6. The result matches committed state without phantom success or stale values.

Separate source/unit checks, rendered evidence, runtime interaction and human
acceptance. A build/mockup does not prove real interaction. Never invent research
participants, timings or usability scores. Respect project-native acceptance gates.
Fix misleading or blocking behavior before decorative polish.
